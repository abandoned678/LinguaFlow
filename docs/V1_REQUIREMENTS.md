# 首版需求与验收

首版 13 项任务于 2026-11-13 全部完成，合并提交为 `811a649`。已在 macOS 27.0.1 上通过文本编辑和 Codex 宿主验收。macOS 26 兼容性仍待验证。

## 产品范围

本输入法基于原生 InputMethodKit 和 Rime 提供简体中文拼音输入，并在光标附近显示中文与设备端英文预览，方便在日常输入中对照阅读。输入不等待翻译，模型缺失或翻译失败时仍可上屏。开发版提供中文输入源及模型准备助手。

翻译仅使用当前会话中本输入法提交的文字和临时候选。原句和译文留在设备端，默认不保留历史。Rime 的词频学习数据存放于独立目录。开发约束和数据流分别见 [AGENTS.md](../AGENTS.md) 与 [ARCHITECTURE.md](../ARCHITECTURE.md)。

### 当前句和预览规则

- 只累计本输入法在当前会话中提交的当前句子，不翻译整个输入框，也不读取历史句子补充上下文。
- 输入停顿约 400ms 后翻译当前句。句子尚未完成时允许预览已有部分，并随继续输入更新。当前组词候选可以参与临时预览，但未上屏前不算已提交文本，不能用于替换。
- `。！？!?` 结束当前句。逗号、顿号、冒号和分号保留在句内。英文句点 `.` 首版不作为强制分句符，避免误切小数及网址。
- 空格在组词时确认高亮候选，后续输入继续累计当前句。上屏后再按空格，宿主插入空格并移动光标，随后输入从新的翻译上下文开始。
- 正常输入换行结束当前句。具体按键服从宿主的换行语义，不能把发送消息误当作换行。句末预览保留到开始下一句或上下文失效。开始下一句时清除旧译文。
- 保留 280 字的缓冲上限。超过上限时暂停该句预览和替换并提示过长，不把截断后的尾部当成整句。
- 在已追踪句尾正常退格时同步更新上下文。移动光标、出现选区、切换输入框／应用／输入法及安全输入时取消翻译并清理上下文。
- 移动窗口和单纯滚动时尝试重新定位浮层。无法取得可靠位置时隐藏，不沿用错误坐标。若同时发现光标或选区变化，按上下文失效处理。

### 替换规则

- 仅在中文已上屏、没有未完成的拼音组词、没有选区、光标位于当前追踪句尾，且译文对应最新原句时启用 `Control + Shift + T` 替换。
- 替换范围仅包含当前句的已追踪原文和句末标点，不包含前面的句子、换行或输入框内其他内容。替换后清理中文追踪上下文和预览，重复触发不得再次改写文本。
- 有未完成组词、翻译未就绪／已过期、句子过长或无法确认替换范围时，不修改原文，不回退到追加译文。提示替换暂不可用。已识别的替换快捷键不得意外透传为宿主提交消息。
- 核对当前句对应的宿主 UTF-16 范围和内容后，调用一次指定范围替换。文本编辑和 Codex 的实测结果见下方验收记录。

## 构建与安装验证

源码基线为 `b966fe6`，开发分支为 `codex/linguaflow-v1`。

- 环境为 Apple Silicon（arm64）、macOS 27.0.1（26A434）、Xcode 27.2（27B52）、Swift 6.4.2。
- 通过 Homebrew 安装 librime `1.17.0_2` 和 OpenCC `1.4.2`，确认 librime 头文件及动态库、OpenCC 工具及数据可访问。
- 词库固定版本为 `rime-essay@e9b1a374a6ea015fca5bdd04318924b4483ac35a`、`rime-luna-pinyin@56b934b099dfbeab842320f13aa8b461a6ab3e42`、`rime-prelude@082425ea0684bca36474415d4a0e8db9b016487e`。

首版验收时，开发版 Bundle 和输入源 ID 均为 `com.abandoned678.inputmethod.LinguaFlowDev`。本地安装位于 `~/Library/Input Methods/LinguaFlowDev.app`，Rime 用户数据位于 `~/Library/Application Support/LinguaFlowDev/Rime`。arm64 测试安装包内含中文开发版、设置助手、librime、OpenCC 和许可证。当前「随键译」的身份和安装路径见 [安装说明](INSTALL.md)。

13 项 XCTest、核心自检、真实 Rime 自检、本地翻译自检、IME 和设置助手的构建均通过。翻译自检首次返回 `TranslationError.notInstalled`，随后确认中英模型已就绪，重跑通过。故障模拟完成后已重装正常开发构建，并再次通过输入源注册及本地翻译检查。

Swift Package 声明最低 macOS 26，本次构建内嵌的 Homebrew librime 要求 macOS 27。验证 macOS 26 需要用符合最低版本的依赖重新构建并在该系统实测。

## 宿主验收

2026-11-13 在 macOS 27.0.1 上进行。文本编辑为 1.21，Codex 桌面版为 ChatGPT.app `26.1029.61003`。正常替换使用 `cbd488c`，浮层定位修复使用 `596d602`。以下两列记录用户用实体键盘确认的结果。Codex 使用未发送测试草稿。

| 场景 | 操作与通过标准 | 文本编辑 E2 | Codex E3 |
| --- | --- | --- | --- |
| 中文上屏与分句 | 上屏「我今天」后继续「想去公园」，预览随整句更新。逗号保留当前句，句号后只预览新句 | 通过 | 通过 |
| 正常替换 | 先粘贴「前文：」，再用该输入法上屏「你好」。待显示 `Hello` 后按替换键，结果为「前文：Hello」 | 通过 | 通过，草稿未发送 |
| 拒绝不可靠替换 | 切换候选，分别在组词、等待译文、移动光标或选中文字后尝试替换。成功后再按一次快捷键。各拒绝场景均保留正文 | 通过 | 通过，草稿未发送 |
| 退格与换行 | 退格删除「天」后预览更新。换行后输入「你好」，只预览新行 | 通过，Return 换行 | 通过，Shift + Return 换行 |
| 浮层定位 | 在多行靠下位置输入，移动窗口或滚动。浮层跟随当前行，定位不可用时隐藏 | 通过 | 通过 |
| 会话清理 | 输入后切换焦点或输入源，旧浮层消失，旧译文不会重新出现 | 通过 | 通过 |
| 翻译失败 | 临时构建将请求延迟 5 秒并模拟模型未安装。失败后收到下载模型的提示，仍可上屏中文，触发替换时保留原文 | 通过 | 通过，草稿未发送 |
| 长句与持续输入 | 连续输入超过 280 字触发提示并保留正文。约 10 分钟组合用例检查卡顿和浮层残留 | 用户反馈正常 | 用户反馈正常 |

旧译文迟到由可控的 XCTest 覆盖。会话取消后迟到的结果和错误均不发布，复用修订号也不会放行旧错误。

- 早期桌面自动化未把拼音按键送入文本编辑的 IMK 按键回调，对 Codex 的访问也被工具拒绝。最终两宿主均通过实体键盘验证。
- 旧键 `Control + Return` 与 macOS 上下文菜单冲突。一次到达输入法的请求也曾因指定范围返回内容不匹配而保留原文。改为 `Control + Shift + T` 后，空白文稿和带前文场景的替换通过。
- Codex「问题」回答框曾在回车后的组词中丢失浮层。修正当前行矩形兜底后，用户确认回答框恢复，普通草稿的多行定位也通过。
