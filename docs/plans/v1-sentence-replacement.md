# 首版主动整句替换 Plan

依据 [Spec](../specs/v1-sentence-replacement.md)。先完成 B3、C2，参考 E1 的宿主探测结果。若某个宿主的范围支持仍无法确认，实现并验证保留原文路径，并在最终宿主验收记录缺口。

## D1 整句替换作为一个提交

1. 定位 `LinguaFlowInputController.handle` 的旧插译分支、`TrackedTextReplacement`、已提交句快照和光标对账。用现有检查入口先复现有风险的行为。
2. 明确当前句的范围及来源。用可控翻译结果验证修订号和已提交原文匹配，覆盖组词、超长、选区、光标变化和不可用宿主。含 emoji 或组合字符时按 UTF-16 校验，确保非零偏移和前文保持正确。
3. 接通快捷键、范围确认、宿主写入、成功后的状态清理与失败提示。同步去掉旧追加／换行插译及对应面板文案。任何无法确认的范围走保留原文路径。
4. 验证成功只写一次，不改变范围外文本。失败、重复触发和收到晚返回的翻译时不得误改或误发。运行核心、Rime 自检并构建 IME 和设置助手。

不把范围工具单独交付为未接线的功能。E2、E3 再验证实际宿主是否接受目标范围及快捷键。

### D1 执行记录

先复现同源文的旧修订译文仍可通过范围检查。新增检查覆盖 UTF-16、旧修订、组词、光标偏移、选区及清理后重复触发。控制器比较宿主当前范围文本后发出一次指定范围写入，替换后清空追踪。旧追加分支和提示已移除。13 项 XCTest、Core、Rime、翻译自检与两项构建通过。宿主实际写入结果见 E2、E3。
