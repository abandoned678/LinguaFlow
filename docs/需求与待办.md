# 中文输入时实时预览英文：需求与待办

整理日期：2026-10-29

当前状态：需求汇总与开发待办；尚未开始本轮功能开发。

开发底座：优先基于 [LinguaFlow](https://github.com/Janglejay/LinguaFlow) 二次开发。

> 本文汇总已有讨论，不代表所有扩展功能均已确认。勾选项表示已有证据；未勾选项表示仍需决定、实现或验证。本文不授权安装输入法、变更系统设置、创建远程仓库或发布软件。

## 1. 我们要解决什么问题

在 Mac 上输入中文时，希望能同时看到对应英文，通过日常打字学习英语。英文预览应出现在当前输入句子或光标附近，并随着输入位置更新，而不是固定在屏幕底部或角落。

主要使用场景包括 Codex 的消息输入框。此前基于辅助功能读取宿主文字的测试未能在 Codex 中工作；调整测试对象后，用户已在 macOS“文本编辑”中看到了测试效果。这只能说明该测试路径在文本编辑中具备可行性，不能推出 Codex 的输入法方案已经可用。

目前选择先验证原生输入法路线：由输入法直接掌握本次输入的内容，减少对外部读取 Codex 文本框的依赖。该路线仍依赖宿主对输入法接口的支持，兼容性必须实测。

## 2. 已确定的核心需求

| 编号 | 需求 | 验收方向 |
| --- | --- | --- |
| R1 | macOS 中文输入时预览英文 | 正常使用拼音输入中文，停顿后显示当前中文对应的英文，无需复制或发送消息 |
| R2 | 预览靠近输入位置 | 优先位于当前输入行下方；下方空间不足时可显示在上方，不固定在屏幕某一角落 |
| R3 | 跟随位置变化 | 连续输入、换行、移动窗口、滚动及切换显示器时验证定位；无法可靠定位时不沿用明显错误的旧位置 |
| R4 | 服务英语学习 | 用户可以对照中文与英文阅读；普通输入不自动用译文覆盖中文 |
| R5 | 本地翻译优先 | 基础功能使用 macOS 本地翻译，不要求 API Key，不依赖第三方翻译服务 |
| R6 | 轻量、输入流畅 | 输入不等待翻译；异步翻译失败或模型未就绪时仍能正常输入中文 |
| R7 | 保护输入隐私 | 不上传原句、译文或输入记录；默认不保存原句和翻译历史，说明输入法词频学习数据与历史记录的区别 |
| R8 | 尽量复用成熟组件 | 基于 LinguaFlow、Rime 和系统翻译能力开发，避免从零重写拼音引擎 |
| R9 | 验证 Codex 场景 | 在真实 Codex 输入框内验证选字、中文输入、英文预览、换行和定位；通过前不宣称兼容 |
| R10 | 主动用英文替换当前中文句子 | 中文已上屏、当前句译文就绪且追踪位置可靠时，按 `Control + Return` 原位替换当前句；不改变输入框内其他内容 |

英文预览使用靠近光标的独立浮层；普通输入不把英文写入宿主文本框。只有用户明确按下替换快捷键时才修改原句。

## 3. 范围与尚未决定的选项

### 当前首版范围

- Mac 上的拼音中文输入及当前整句的本地英文预览。
- `Control + Return` 将当前已追踪的中文句子原位替换为对应英文；不追加译文、不另起一行插入。上游快捷键的追加语义需要改为替换。
- 首版不提供独立英文输入源、英文到中文预览、英文补全或纠错；不要求删除所有相关源码。
- 首先验证文本编辑和 Codex，再扩展常用宿主的兼容性。
- 预览可用性、输入稳定性和隐私边界优先于外观扩展。

### 当前句和预览规则

- 只累计本输入法在当前会话中提交的当前句子，不翻译整个输入框，也不读取历史句子补充上下文。
- 输入停顿约 400ms 后翻译当前句；句子尚未完成时允许预览已有部分，并随继续输入更新。当前组词候选可以参与临时预览，但未上屏前不算已提交文本，不能用于替换。
- `。！？!?` 结束当前句；逗号、顿号、冒号和分号保留在句内。英文句点 `.` 首版不作为强制分句符，避免误切小数及网址。
- 正常输入换行结束当前句；具体按键服从宿主的换行语义，不能把发送消息误当作换行。句末预览保留到开始下一句或上下文失效；开始下一句时清除旧译文。
- 保留 280 字的缓冲上限。超过上限时暂停该句预览和替换并提示过长，不把截断后的尾部当成整句。
- 在已追踪句尾正常退格时同步更新上下文。移动光标、出现选区、切换输入框／应用／输入法及安全输入时取消翻译并清理上下文。
- 移动窗口和单纯滚动时尝试重新定位浮层；无法取得可靠位置时隐藏，不沿用错误坐标。若同时发现光标或选区变化，按上下文失效处理。

### 替换规则

- 仅在中文已上屏、没有未完成的拼音组词、没有选区、光标位于当前追踪句尾，且译文对应最新原句时启用 `Control + Return` 替换。
- 替换范围仅包含当前句的已追踪原文和句末标点，不包含前面的句子、换行或输入框内其他内容。替换后清理中文追踪上下文和预览，重复触发不得再次改写文本。
- 有未完成组词、翻译未就绪／已过期、句子过长或无法确认替换范围时，不修改原文，不回退到追加译文；提示替换暂不可用。已识别的替换快捷键不得意外透传为宿主提交消息。
- 优先通过宿主支持的定范围替换接口完成，不用模拟多次退格猜测删除范围。必须在文本编辑和 Codex 中分别实测，不预先承诺两个宿主都支持可靠替换。

## 6. 开发时必须遵守的边界

- 输入热路径保持本地，不等待翻译。翻译是预览，只有用户明确操作时才允许插入或改变宿主文本。
- 仅追踪本输入法在当前输入会话中掌握的内容；不得为了补上下文扫描任意宿主历史。
- 失焦、停用、安全输入及无法验证的编辑发生时，取消翻译并清理不可靠的上下文。
- 默认不保存原始句子和译文。若以后改变，需要单独的产品决定和用户控制。
- 行为变更前先添加有意义的失败检查；输入变更后运行核心与 Rime 检查，UI／翻译变更后构建 IME 和设置助手。
- 安装与卸载前先审查精确目标；开发版使用独立身份和数据目录，不直接覆盖原版或其他输入法的数据。
- 保留第三方许可；不直接复制与当前许可策略冲突的 GPL 输入法前端代码。
