# 随键译的架构决策记录

当本次任务要决定可长期影响模块、进程或本地数据边界的方案时，主 Agent 记录选择理由。例如评估是否应把测试工具拆成独立 Swift package，需同时考虑开发者能否单独发布工具、如何保证与输入法构建匹配，以及需要维护哪些接口。

在负责该行为的规格文档中增加一小节即可。决定跨越多份规格或需要被多处长期引用时，可单独保存为 `docs/decisions/YYYY-MM-DD-主题.md`，从相关规格链接过去。普通缺陷修复的重现及验收记录留在对应测试或任务里。

| 字段 | 内容 |
| --- | --- |
| 背景与状态 | 日期、涉及的用户行为或工程边界、待决定或已采纳、相关规格 |
| 备选方案与依据 | 影响当前选择的可行方案、代码位置、实测证据及尚待验证的假设 |
| 选择与代价 | 采用哪种方案、为什么、需要维护什么，以及已知限制 |
| 验证与重评 | 如何验证选择，有哪些新事实会触发重新评估 |

提出建议时标明仍待决定的内容。已有决策变更时记录新日期及取代理由，从旧记录链接到新结论，以便下一次评审追溯。
